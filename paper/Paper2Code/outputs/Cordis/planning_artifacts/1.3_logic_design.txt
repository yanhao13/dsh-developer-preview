[Shared Knowledge]
All modules use `Key` as `string | symbol` and `Dispose` as `() => void | Promise<void>`. The root symbol slots `@@store`, `@@isolate`, and `@@intercept` are private to `Context`; all coeffect access goes through `Context.get/set/isolate/intercept`. Fiber UIDs are global monotonically increasing integers; target and committed views are `Map<Key, number>` where the number is a provider fiber UID. The lifecycle is inertial: once a transition task is scheduled via `fiber.inertia`, `refresh` does not start another transition until the current one completes. The `notify(ctx, keys)` helper must be executed on the context that owns the changed store; dependents are matched by comparing resolved realms. The loader treats `Entry.id` as the reconciliation key. HMR's `getImports` is a static scanner; tests should use simple relative imports only.

----------------------------------------
[Anything UNCLEAR]
The paper does not define how `provided(fiber)` is computed when a component declares `provide` but writes only a subset of it; we instrument `ctx.effect` to record written keys and use the declared `provide` as a fallback. Interception metadata merge semantics are per-key and require user-supplied merge functions; the default is right-biased overwrite. The HMR import graph without bundler hooks cannot reliably handle dynamic imports or virtual modules; for reproduction we restrict to statically analyzable fixtures. Observational equivalence `≃` is application-defined; property tests use deep equality and a custom `per-key equivalence` hook.
