[Implementation approach]
We implement a TypeScript meta-framework that directly mirrors the paper's Cordis architecture. The core is a first-class Context object carrying symbol-keyed slots (@@store, @@isolate, @@intercept) and a single effect primitive, ctx.effect, built on async generator iterators: each yielded value is an inverse, and the runtime composes them LIFO into an accumulator. Coeffect operations (set/get/isolate/intercept) are implemented as effects on the store and as derived child contexts; notify() re-evaluates affected fibers' target views. The fiber lifecycle implements the inertial state machine of Section 4.3: refresh computes target, reload executes the component's effect iterator while committing a resolved view, and unload drains dependents (guarded withdrawal) before running the accumulator. The loader reconciles declarative entry trees via keyed diff and managed isolation realms. HMR performs module classification (accepted/declined), stale-entry detection, and transactional reload with cache backup/restore. We use Vitest for the test suite and fast-check for property-based validation of recovery exactness, ordering, progress, and confluence. The reference (mock) plugin ecosystem is a small Koishi-like set: db-provider, adapter, command, and admin-console components.

[Anything UNCLEAR]
The paper does not specify the merge semantics for interception metadata beyond right-bias; we require each key to supply a merge function or default to overwrite. The provided(fiber) set is not tracked explicitly in the formal model, so we instrument effect execution to record keys actually written and fall back to the component's provide declaration. HMR's import graph is abstract; without bundler hooks, static scanning may miss dynamic imports. The observational equivalence for state recovery is application-defined; we default to deep equality and allow per-key equivalence hooks in tests.
